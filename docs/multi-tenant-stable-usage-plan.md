# CLIProxyAPI 多人稳定使用推荐方案（MVP）

> 目标：在不大改架构的前提下，让团队内多人稳定、安全、可审计地使用 OpenAI 模型（经 CLIProxyAPI/cliproxy）。

## 1. 适用场景

- 面向团队（多人）持续使用，不是一次性临时试用。
- 需要基础的配额、限流、审计和故障隔离能力。
- 希望后续开发同学和 AI 工具能快速接手。

## 2. 推荐方案（最小可运营闭环）

### 2.1 鉴权与租户隔离

1. 每个用户/系统发放独立 token（禁止共享主 token）。
2. token 绑定 tenant/user 元信息（如 owner、用途、过期时间）。
3. 支持 token 状态：active / disabled / rotated。

### 2.2 限流与配额

1. 按 token 实施速率限制（QPS/并发）。
2. 按天/月配额（请求次数、token 消耗、费用上限）。
3. 超限返回明确错误码（便于客户端处理）。

### 2.3 模型路由与白名单

1. 按 token 配置可用模型白名单。
2. 支持模型别名（对外稳定名 -> 实际上游模型）。
3. 支持 fallback（主模型失败时兜底模型）。

### 2.4 可观测与审计

1. 记录调用审计（时间、token、模型、耗时、状态码、用量）。
2. 成本统计按 tenant/user 聚合（日/周/月）。
3. 异常告警：401/429/5xx 激增、费用突增、单 token 异常高频。

### 2.5 密钥与安全

1. 上游密钥与业务 token 分离管理。
2. 定期轮换（建议 30~90 天，按风险等级）。
3. 避免在日志输出明文密钥/token。

---

## 3. 实施优先级（1周 MVP）

### P0（必须）

- 子 token 发放与禁用
- token 级限流（基础）
- 基础审计日志（请求维度）
- 模型白名单

### P1（建议）

- 配额（日额度/月额度）
- 成本聚合报表
- 异常告警（429/5xx/费用突增）

### P2（后续）

- 管理后台（可视化）
- 自动轮换辅助流程
- 更细粒度策略（按 API 路径/模型类别）

---

## 4. 配置约定（建议）

- 环境区分：dev/staging/prod
- 配置来源：统一配置文件 + 环境变量覆盖
- 每个 token 的策略结构建议包含：
  - `token_id`
  - `owner`
  - `status`
  - `model_allowlist`
  - `rate_limit`
  - `quota_daily`
  - `quota_monthly`
  - `expires_at`

---

## 5. 运维SOP（最小）

1. 新用户接入：创建 token -> 绑定策略 -> 回传接入文档
2. 异常封禁：禁用 token -> 通知 owner -> 排查日志
3. 轮换：创建新 token -> 灰度切换 -> 废弃旧 token
4. 回滚：模型路由回退到稳定模型，恢复服务可用性优先

---

## 6. 给开发/AI 工具的快速上手

### 开发者

1. 先看本文件（目标与边界）
2. 先实现 P0 能力，不跨阶段提前做复杂后台
3. 所有新增接口必须带审计字段

### AI 工具（Codex/Claude 等）

1. 优先阅读本文件和 README
2. 实现时遵守“先 P0、后 P1”的边界
3. 不输出或提交任何明文密钥
